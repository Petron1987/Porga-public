# Porga 1.0 架构与版本路径 · 草案

当前运行基线是 **0.4.0 Early Alpha**，已交付 M1 的有限切片。项目章程、授权、两类受限团队、
任务图快照、人工成果验收和外部项目 SDK/CLI 已可使用。任务仍串行执行；一般化组队、持久调度、
知识晋升、实际改进采用和回滚待分阶段交付。以[验证记录](../verification-v0.4.md)为当前证据，
以[A1 交付计划](delivery-plan.zh-CN.md)为阶段依赖和验收依据。

## 复用边界

| 组件 | 当前定位 | Porga 自己负责的部分 |
|---|---|---|
| OpenAI Agents SDK | 已接入。Agent、Runner、模型适配与函数工具调用 | 团队候选、角色权限、任务生命周期和确定性验证 |
| Pydantic、SQLite | 已接入。数据校验与本机持久化 | 领域协议、状态迁移、预算与审批账本 |
| 工作流引擎、服务端数据库 | 有明确需求时评估。Temporal、PostgreSQL 是候选 | 业务幂等、租约约束、项目隔离、费用和动作对账 |

能力放在已有应用服务与内核之后。新增 SDK/CLI/Skill/MCP/HTTP 入口复用同一套项目、
授权、预算和验证规则。第三方组件选型先记录候选、依赖版本、许可、最小实验和替换条件。

## 建议版本节奏

版本号是排期草案。若一个版本需要拆分，以各项实际验收和兼容性为准。

| 建议版本 | 交付重点 | 发布所需证据 |
|---|---|---|
| 0.1–0.4 | 已有基础内核、恢复治理、章程/受限组织、外部项目契约 | 对应版本的验收记录 |
| 0.5 | M1 轻量启用，项目盘点、章程草案、解释团队选择；接入 Skill 紧随稳定入口 | 外部合成项目从明确启用到人工接受，授权缺口和未支持情况可核对 |
| 0.6 | MCP 先提供有限结构化操作；按需求交付 M2 单 Worker 和持久任务 | 入口规则一致；长任务通过崩溃恢复、重复投递、预算和取消演练后再开放 |
| 0.7 | M3 项目知识与声明式 Skill 晋升 | 可复核来源、范围、过期、撤销与拒绝越权 |
| 0.8 | M4 第一次受控改进 | 预先冻结基线、独立案例及门禁；候选经人工批准后单独发布并演练回滚 |
| 0.9 | M5 组织变更和 M6 领域复用 | 对照评估组织变更；合成领域模板复用同一内核并保持隔离 |
| 1.0 | 稳定单人项目工作流、外部契约和发行维护 | 实际代表任务、兼容性矩阵、干净环境安装、数据迁移、故障恢复及发布回滚证据 |

上述 1.0 建议保留人工对重大决定的控制。M7 多用户和跨设备服务另行确定范围；
HTTP 和常驻 Worker 依实际需要交付。公开 Alpha 可独立于 1.0 准备。
