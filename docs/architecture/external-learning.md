# A1 External Learning

External discovery is a planned input to the improvement loop. Run evidence identifies a real problem. Public documents, research, and recordings may suggest a candidate method. Discovery, summary, verification, evaluation, approval, and adoption are separate states.

A ResearchWatchSpec scopes questions, sources, project, schedule, budget, maximum items and experiments, validity, stops, and notifications. A future scheduler handles deduplication, incremental checks, and missed triggers. Scout, Distiller, Verifier, and Experimenter are responsibilities that may reuse existing approved roles. Keep verification independent.

A SourceRecord stores provenance, original and canonical URLs, version, date, digest, access rights, and duplication relationships. A connector checks protocols, hosts, redirects, timeouts, sizes, and credentials. Treat retrieved text and media as untrusted data.

| Evidence | Required coverage note |
|---|---|
| Article or release note | Which text and version were actually read. |
| Audio or subtitles | Access source, timestamp range, language, omissions, and transcription confidence. |
| Demonstration | Which frames were reviewed and which claims require visual evidence. |
| Code | Exact version, file, license, and any associated test. |
| Secondary source | Use as a lead and identify the first-party material. |

Separate author claims, observed facts, self-reported results, applicability, interpretation, and missing evidence. Cite a specific passage or time range for each claim. Bind a proposed improvement to an internal issue, baseline, expected change, counterexample, budget, and stop condition. Handle external transfer and transcriptions under the existing consent policy.

M2 provides durable execution. M3 provides provenance, scope, and promotion. M4 provides frozen experiments and owner-controlled adoption. Changes to kernel policy, permissions, budget, or evaluators go through separate engineering and owner review. Test duplicates, conflicting evidence, missing coverage, prompt injection, budget exhaustion, and leakage. See the [source-card example](../research/lauren-tan-workflow-source-card.md).
