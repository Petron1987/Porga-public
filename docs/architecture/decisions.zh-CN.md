# A1 架构选择与待决事项

这是设计决策记录。它不授予付费、联网工具、外部发布或多人服务权限。
“本轮采用”指架构规划使用此方向，运行实现仍受当前范围与各阶段验收约束。

| ID | 规划选择 | 理由与代价 | 何时重新评估 |
|---|---|---|---|
| A01 | 保留原 L1–L5 目标层，Owner 在层外 | 不把一次 CLI 视图误当完整平台；领域与运行视图分开 | 原目标经 Owner 改变 |
| A02 | Python 模块化单体，显式端口/Repository | 适配当前单人本地，减少部署面；需严格避免跨模块随意改表 | 独立扩缩/安全隔离/共享服务需求出现 |
| A03 | 继续 Agents SDK 作为执行适配器 | 复用模型/工具循环；组织、状态、审批仍属 Porga | 具体任务/质量/费用证明需另一适配器 |
| A04 | 关系状态 + Outbox/Inbox + 有限本地 Worker | 为短工作流建立清晰事务与恢复语义；不自研完整分布式引擎 | 多日等待、复杂补偿或 Worker 版本切换超出可维护范围 |
| A05 | 不承诺外部动作 exactly-once | 队列/DB 无法单独决定外部动作是否发生；保留 receipt/unknown/reconcile | 仅按各连接器真实幂等能力细化 |
| A06 | 六类带范围/时效的知识先于向量检索扩展 | 原文存储不是学习，向量相似度不是授权 | 检索评估证明需要嵌入/向量索引 |
| A07 | 先研究 Prompt/声明式 Skill 改进，再组织拓扑改进 | 限定变化面，先证明候选—实验—采用闭环 | M4 的质量与回退验收通过 |
| A08 | 采用是独立发布步骤，不等于批准 | 可绑定精确摘要、幂等激活、监控和回滚 | 兼容/授权要求变化 |
| A09 | 当前所有提案人工决定；分级自动采用待 Owner 政策 | 保留“少打扰”的目标，但不能拿愿景自授权限 | 有明确低风险范围、独立门禁和审计证据 |
| A10 | 组织修订不可变，旧任务固定版本 | 避免运行中 Prompt/角色漂移；需保留多版本及迁移规则 | 仅在明确的安全撤销/迁移流程下改变旧任务 |
| A11 | 领域模板仅用公开或合成资料，不含业务私有数据与凭据 | 验证通用框架与领域适配边界 | 真实业务独立评审后 |
| A12 | 多机阶段再迁移中心服务/数据库 | 本地可靠性不等于共享服务；避免网络盘同步 SQLite | Owner 确认多人/跨机范围和运维责任 |
| A13 | 对外接入按轻量 SDK/CLI → 薄层 Skill → MCP → 按需 Worker/HTTP 推进，各入口共用内核 | Owner 于 2026-11-06 确认；降低半成品项目接入成本，保留权限边界，避免重复建设执行逻辑 | 对应接入验收未通过或出现实际服务/长任务需求时细化；M2/M7 依赖不被接口顺序替代 |

A13 的完整交付范围见 [四步接入规划](delivery-plan.zh-CN.md#外部接入与分发的四步交付顺序)。
接入不设业务成熟度门槛；数据访问、外发、费用和修改权限仍需授权。
薄层接入 Skill 与 M3 的可学习 SkillPackage 分别验收；本决策不声称任何新接口已实现。

## 尚未确定的产品与政策问题

- 第一个真实项目的成功标准、费用/延迟上限、允许的数据源和停止条件。
- 留出集管理者、统计可信度/重复次数、不同任务的硬门槛及人工纠正方式。
- 哪类低风险变更可预授权采用，哪类必须人工决定；预算/权限增额永远不由候选自批准。
- 知识时效、删除/保留、跨项目晋升授权和归因撤销政策。
- 本地持续 Worker 的运行窗口、告警规则、备用恢复位置和服务可用性要求。
- 是否、何时需要 PostgreSQL、Temporal、对象存储或 UI；具体产品版本/服务商另行评估。
- Community 0.4.0 的许可证为 MIT，官方公开仓库为 `Petron1987/Porga-public`。
  其他分发渠道、商标和命名空间按实际发布需要另行核验。

这些问题不妨碍先实现 M1 的协议与受限注册表，但在依赖它们的动作前必须具体化。
架构允许缺口作为明确的待决对象存在，不要求模型“猜完一切”才算自主。

## 需要避免的五种架构漂移

1. 给固定 Research/QA 加更多提示词，就宣称完成动态组织。
2. 存下对话并建立向量索引，就宣称完成知识/Skill 晋升。
3. 让同一个候选生成者自行修改评估集并打分，再据此自动采用。
4. 采用 Redis/Temporal/云服务器，就宣称已经实现连续经营和可靠外部动作。
5. 把文档修订号 A1、软件版本 v0.2、能力阶段 P2、Agent/组织版本混为一谈。

相关边界须在 PR、发布说明和产品界面中保持一致；未通过对应阶段验收的功能明确标为设计。
